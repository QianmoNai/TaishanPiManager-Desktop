# 第三方插件包开发指南

本文面向希望为 TaishanPi RK3566 开发工具的开发者。当前插件格式是一个很小的、可审查的 ZIP 包：桌面端负责展示页面和调度任务，插件作者负责提供板端 POSIX Shell 脚本。

用户在“插件中心 → 导入第三方插件包”选择 ZIP。导入阶段只校验和保存文件，不连接设备、不执行脚本。用户打开插件页面并点击操作后，才会在当前选中的泰山派上运行脚本。

## 先看一个最小可用插件

仓库自带 [设备信息示例](../examples/device-info/)，包含一个一次性操作和一个状态页面。复制到自己的目录后，可以先把它改成自己的插件：

```powershell
Copy-Item examples/device-info my-plugin -Recurse
Rename-Item my-plugin/plugin.json my-plugin/plugin.json
```

目录必须是：

## 包结构

```text
device-info.zip
├── plugin.json
└── scripts/
    ├── info.sh
    └── status.sh
```

ZIP 根目录必须直接包含 plugin.json，不能再套一层文件夹。完整示例见 [examples/device-info](../examples/device-info/)。在项目根目录用 PowerShell 打包：

```powershell
Compress-Archive -Path examples/device-info/plugin.json,examples/device-info/scripts -DestinationPath device-info.zip
```

检查 ZIP 是否正确：

```powershell
Expand-Archive device-info.zip .\check-plugin -Force
Get-ChildItem .\check-plugin -Recurse
```

压缩包内应该直接看到 `plugin.json` 和 `scripts/`，而不是 `device-info/plugin.json`。

发布到开发者自己的 GitHub/Gitee Releases，用户下载后本地导入即可；本版本不提供在线商店或自动更新。

## manifest 字段

- `schema_version`：固定为整数 1。
- `id`：例如 `org.example.device-info`，小写字母、数字、点和短横线组成，至少一个点或短横线；作为本地唯一标识。
- `name`、`version`、`author`、`description`：必填字符串。作者字段为自述，并非身份认证。
- `actions`：1–12 个操作，每项含 `title` 和 `script`。脚本路径必须为 `scripts/名称.sh`。
- `page`（可选）：声明独立桌面页面。`title` 是窗口标题；`cards` 是最多 12 个状态卡片，每项含唯一 `id` 和 `title`；`poll` 可指定 JSON 输出脚本、`interval_ms`（1000–60000）和固定的 `format: json`。

一个完整的 manifest 示例：

```json
{
  "schema_version": 1,
  "id": "com.example.temperature",
  "name": "温度监控",
  "version": "1.2.0",
  "author": "Example Developer",
  "description": "读取 CPU 和板端温度并提供健康检查。",
  "actions": [
    {"title": "执行健康检查", "script": "scripts/check.sh"},
    {"title": "查看内核信息", "script": "scripts/kernel.sh"}
  ],
  "page": {
    "title": "温度监控",
    "cards": [
      {"id": "cpu", "title": "CPU 温度"},
      {"id": "board", "title": "板端温度"},
      {"id": "status", "title": "健康状态"}
    ],
    "poll": {
      "script": "scripts/status.sh",
      "interval_ms": 5000,
      "format": "json"
    }
  }
}
```

字段选择建议：

| 字段 | 用途 | 注意事项 |
| --- | --- | --- |
| `id` | 插件唯一身份 | 发布后不要修改；更新使用相同 ID 和更高版本号 |
| `version` | 人类可读版本 | 建议使用 `主版本.次版本.修订` |
| `actions` | 用户主动点击的操作 | 每项都应短、明确、可重复执行 |
| `page` | 独立桌面页面 | 没有页面的插件可以省略 |
| `cards` | 页面状态卡片 | 卡片 ID 必须唯一，脚本 JSON 的键与它对应 |
| `poll` | 后台状态任务 | 只输出 JSON，不要输出日志或提示文字 |

仅支持 UTF-8 manifest 与 Shell 脚本；页面使用内置 Qt 容器和声明式卡片，不支持注入 Python/Qt 动态模块、自定义任意桌面控件、额外二进制资源或依赖安装器。ZIP 及解压内容均不超过 2 MiB，文件至多 32 个，单个脚本至多 64 KiB。导入拒绝路径穿越、符号链接、重复路径和未声明文件，不直接解压不可信路径。

## 编写操作脚本

每个操作经用户确认后，通过 ADB 将脚本传给设备上的 `timeout 60 sh -s`，以当前 ADB Shell 权限执行（通常是 root）。板端需要 `sh` 和 `timeout`；不能依赖 Bash 扩展、`systemd` 或交互输入，除非你先检测目标固件确实提供它们。

推荐脚本模板：

```sh
#!/bin/sh
set -eu

if [ ! -r /sys/class/thermal/thermal_zone0/temp ]; then
    echo "thermal sensor unavailable" >&2
    exit 2
fi

awk '{printf "CPU: %.1f C\\n", $1 / 1000}' \
    /sys/class/thermal/thermal_zone0/temp
```

脚本应遵守这些约定：

- 使用 `#!/bin/sh` 和 `set -eu`；
- 先检测命令、文件和目录是否存在，再读取或修改；
- 错误写入 stderr，并使用非零退出码；
- 输出面向用户，避免循环打印大量内容；
- 使用绝对路径，不依赖当前工作目录；
- 不把密码、令牌或私钥写进 ZIP；
- 安装服务前提供对应的停止、状态和卸载操作；
- 不使用 `rm -rf` 清理不确定路径。

当前每次操作最多运行 60 秒。桌面端显示标准输出和错误输出，显示区域取末尾约 64 KiB；底层 ADB 输出超过 2 MiB 会被拒绝。

页面打开时，`poll` 脚本在后台线程按间隔运行，必须输出 JSON 对象，例如 `{"uptime":"2h","load":"0.12"}`；对象中与卡片 `id` 同名的值会更新到对应卡片。关闭页面、切换设备或退出软件会停止轮询。轮询复用应用的设备任务队列，不会阻塞窗口，但也不会与其他设备操作并发执行。

轮询脚本示例：

```sh
#!/bin/sh
set -eu

temp="unknown"
if [ -r /sys/class/thermal/thermal_zone0/temp ]; then
    temp=$(awk '{printf "%.1f C", $1 / 1000}' /sys/class/thermal/thermal_zone0/temp)
fi

load=$(cut -d' ' -f1 /proc/loadavg 2>/dev/null || printf 'unknown')
printf '{"cpu":"%s","board":"%s","status":"%s"}\n' "$temp" "$load" "ok"
```

JSON 规则：

- 必须是一个 JSON 对象，不能在 JSON 前后打印调试文字；
- 卡片 `id` 为 `cpu` 时，脚本输出 `{"cpu":"..."}` 才会更新该卡片；
- 缺少的键显示 `—`；
- 值会被转换成短文本显示，建议控制在 200 字符以内；
- 轮询间隔为 1000–60000 毫秒，建议硬件状态使用 3000–10000 毫秒；
- 轮询失败不会阻塞窗口，会在页面输出区域显示错误。

长驻服务应由插件显式管理，开发者自行提供查询、停止和卸载操作。不要在脚本里放凭据；下载外部资源应校验哈希。脚本不是沙箱，可以修改设备和访问网络，用户应仅运行可信来源的包。60 秒超时不保证停止脚本脱离会话启动的后台服务。显示输出截取末尾 64 KiB，底层超过 2 MiB 输出会报错；请控制输出量。

## 能开发什么

当前 API 适合以下插件：

- CPU、内存、温度、磁盘和进程状态卡片；
- Wi-Fi、以太网、DNS、路由和端口连通性诊断；
- GPIO、I²C、SPI、PWM、串口和 LD06 设备检测；
- 服务状态、启动、停止、重启和日志查看；
- 配置备份、恢复、校验和版本检查；
- 一键安装板端脚本、定时任务和自定义服务；
- 生成诊断报告并通过操作输出给用户。

桌面页面目前是声明式的，插件可以提供标题、状态卡片和按钮，不能注入任意 Qt 控件。插件包也不能直接访问 Windows 文件系统、电脑串口或桌面端 Python。

## 安装板端组件的建议流程

如果插件需要安装板端服务，建议提供四个操作：

1. `检查环境`：检查架构、命令、目录、剩余空间和已有版本；
2. `安装或升级`：写入文件、设置权限、安装启动项，然后验证文件哈希；
3. `查看状态`：输出版本、进程、最近日志和配置位置；
4. `停止并卸载`：先停止服务，再只删除自己创建的固定文件。

安装脚本要允许重复执行，升级失败时保留备份。卸载脚本不要删除用户数据，除非在操作名称和执行前提示中明确说明。

## 本地开发工作流

```powershell
# 1. 创建插件目录
New-Item -ItemType Directory -Force my-plugin/scripts

# 2. 编辑 plugin.json 和 scripts/*.sh
# 3. 打包
Compress-Archive -Path my-plugin/plugin.json,my-plugin/scripts \\
  -DestinationPath my-plugin.zip -Force

# 4. 导入软件测试
# 插件中心 → 导入第三方插件包 → 打开页面
```

建议至少测试：没有连接设备、USB ADB、网络 ADB、设备断开、命令缺失、权限不足、服务已经运行和重复安装。对会修改设备的操作，应在测试设备上验证恢复和卸载。

## 发布清单

- ZIP 根目录没有额外的顶层目录；
- `plugin.json` 的 ID、版本和作者信息正确；
- 所有脚本都是 UTF-8、LF 换行、可由 `/bin/sh` 执行；
- 操作脚本和轮询脚本都能在没有目标硬件时给出清楚错误；
- 不包含密码、私钥、访问令牌、无关二进制文件或个人数据；
- 提供 README，说明支持的 Buildroot 版本、架构、依赖、安装路径和卸载方法；
- 为每个发布包计算 SHA-256，并在发布页写明校验值；
- 使用 GitHub/Gitee Release 发布 ZIP 和变更说明，而不是把二进制塞进源码目录。

## 故障排查

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| 导入失败：格式版本 | `schema_version` 不是 1 | 修改为整数 `1` |
| 导入失败：未声明文件 | ZIP 中有 README、图片或隐藏目录 | 第一版只保留 `plugin.json` 和 `scripts/*.sh` |
| 页面卡片一直显示 `—` | JSON 键与卡片 ID 不一致 | 检查 `cards[].id` 和脚本输出键名 |
| 轮询结果无效 | 输出混入了调试文字 | 只保留一行 JSON，调试内容写 stderr |
| 操作超时 | 命令等待输入或启动了长任务 | 使用非交互参数和 `timeout`，拆分安装与服务启动 |
| 设备操作失败 | ADB 断开、权限不足或命令不存在 | 先做环境检查并输出具体错误 |
| 更新被拒绝 | 同 ID 包已经导入 | 在插件中心移除旧包后再导入新版 |

## 安装与更新

包保存在 Qt AppLocalDataLocation 的 `third-party-plugins` 中，独立于 EXE 目录。同 ID 包不会静默覆盖；更新需先移除旧包再导入新版。移除会把旧包归档到其 `removed` 子目录，可重新导入恢复。

“已导入”仅表示本机保存了插件包，无法推断板端状态。移除本地包不会自动执行卸载脚本、停止服务或删除板端文件。

## 安全边界

插件脚本不是沙箱。泰山派当前 ADB Shell 很可能拥有 root 权限，因此一个恶意插件可以修改系统、读取文件、访问网络或破坏设备。导入包前应核对来源、作者、版本和 SHA-256；运行修改类操作前应阅读软件显示的脚本和目标设备。

当前版本没有插件签名验证、在线市场、权限声明、自动更新和回滚安装。需要向普通用户发布时，建议先在项目或 Release 页面提供源代码、变更记录、校验值和支持渠道。
